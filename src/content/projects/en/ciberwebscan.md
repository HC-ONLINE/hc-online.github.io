## Overview

CiberWebScan centralizes different stages of web application assessment into a single modular tool. It can start with passive reconnaissance and analysis of technologies, SSL/TLS configuration, security headers and resources, and extend the workflow to scraping and controlled active testing.

## Architecture

The tool separates its interfaces, service orchestration, and specialized analysis, scraping and testing components.

![CiberWebScan architecture diagram](/images/projects/ciberwebscan/architecture.png)

## Capabilities

**Analysis and reconnaissance**

- Technology fingerprinting
- SSL/TLS analysis
- Security header assessment
- CVE correlation
- Static and dynamic web scraping

**Controlled active testing**

- XSS
- SQL injection
- Path traversal
- CSRF
- Directory enumeration
- Subdomain enumeration
- OS command injection

> Active testing is disabled by default and requires explicit consent before execution, together with configurable target restrictions.

## Engineering

- **HTTP client** — Centralized HTTP client with retry and backoff, domain-level rate limiting, adaptive AIMD behavior, proxy support, HTTP/2 and structured logging.
- **Modular architecture** — Services orchestrate independent analyzers, attack modules and scraping engines while keeping core logic decoupled from the CLI and API layers.
- **REST API** — FastAPI-based API with API key authentication, rate limiting, configurable CORS, health endpoints and temporary result downloads.
- **Configuration** — Pydantic-based configuration with YAML profiles and environment-variable overrides.
- **Export** — Results can be exported as JSON, JSONL, CSV and HTML.
- **Quality** — Automated CI across Python 3.10–3.12 with pytest, Ruff, Pyright and pre-commit.

## Security Model

CiberWebScan separates passive analysis from active testing. Active modules remain disabled by default and require explicit consent before execution. Configurable target restrictions and intensity levels provide additional safeguards against unintended testing.

**Current limitations**

- The REST API is currently in beta.
- API download tokens are currently stored in memory.
- The deep scan architecture is planned but not fully implemented.
- Some fingerprinting options are not yet fully connected to the orchestration layer.
